# Tuti Stage 1 — live Persian transcript in the macOS app

> Execute task-by-task; checkbox steps. Native in-session execution.
> Git rule for this repo: nothing commits without Amir's explicit ask.

**Goal:** speak into the tuti macOS app, watch the raw Persian text appear live.

**Architecture:** Swift app owns mic + UI, launches the Python sidecar (`server.py`, PEP-723,
`uv run`) and streams float32 PCM to it over `ws://127.0.0.1:8765`. The server ports
`LiveSession` from `nemotron-asr-streaming-farsi/scripts/gradio_app.py` (soxr resample,
RNN-T streaming, idle timeout) and emits growing text prefixes.

**Spec:** conversation 2026-11-08 — 3-stage plan (link → cleanup LLM → agent LLM);
this doc is stage 1 only. Hotkey: deferred. Model stack versions pinned to the ASR
repo's script env.

## Global constraints

- Protocol v1: JSON text frames `{"v":1,...}` (real unicode, no escaping), binary
  float32 PCM frames (any sample rate; server resamples). Types implemented now:
  `control` / `asr_partial` / `asr_final` / `error`. Reserved for stages 2-3:
  `clean_final`, `agent_reply`, `tool_request`, `tool_result`.
- No hotkey, no TTS, no LLM calls, zero third-party Swift dependencies.
- Python deps: transformers==5.18.0, torch, librosa (the feature extractor imports it), numpy, soxr, websockets>=14.
- Model `mehdi-hf/nemotron-asr-streaming-farsi`, device auto (mps), lookahead 13.

## Review focus (failure modes the smoke test must pin)

- 48 kHz mic chunks into a 16 kHz model → soxr path exercised by streaming 48 kHz audio.
- Client disconnect mid-recording → `finish()` on disconnect + 10 s idle timeout; model never held forever.
- Double `start` → `error` message, no second session.
- Late binary chunk after `stop` → dropped (feed guard).
- `asr_final` exactly once per recording; `error` type instead when transcription fails.
