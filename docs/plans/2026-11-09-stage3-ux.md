# Stage 3 + UX batch — implementation plan

**Goal:** tuti becomes a daily tool: system-wide hotkey with paste-back, menu-bar presence,
voice actions (stage 3 mini), card management (search/edit/delete/raw view), paragraphed
finals, per-call before/after LLM log, and a token counter.

**Architecture:** the Python side grows two LLM paths (clean + intent) over the existing
`llm_clean` client, both logged per call to `llm_calls.jsonl` with token usage, and both
reporting cumulative usage to the app over the existing socket. The Swift side adds a Carbon
hotkey + paste-back flow, a `MenuBarExtra` scene, and card-management state on the existing
view model. Paragraphing is a pure client-side formatter on finalized text — locked text is
never re-sent.

**Spec:** the idea list Amir approved on 2026-11-09 ("همشو مرتب تمیز بزن. جانبی‌هارو
نمی‌خوام") plus his two additions: a before/after capture for prompt testing, and token
usage if not complex.

## Decisions

- **Hotkey:** fixed **⌥Space** (Carbon `RegisterEventHotKey`, no dependency). Start from any
  app → record; press again → stop. Recording started with the in-app button/Space never
  pastes; hotkey-started recordings paste into the app that was frontmost at start
  (reactivate + synthetic ⌘V, needs Accessibility trust — checked, with a one-line hint).
- **Menu bar:** `MenuBarExtra` (status, record toggle, last 5 cards copy-on-click, token
  line, Launch-at-Login toggle via `SMAppService`, Open Tuti, Quit). Closing the window now
  hides to the menu bar instead of quitting — quit lives in the menu bar.
- **Voice actions:** after the final clean, the server makes ONE extra LLM call
  (`prompts/intent.md`, max_tokens 300) classifying the transcript as
  `reminder|search|open|none` + fields (Persian relative dates → ISO by the LLM). The app
  renders an action chip on the card — a click executes (Reminders via osascript, Google
  search, open URL); nothing auto-executes. No `.env` → no intent calls. Bad JSON → dropped.
- **Cards:** search field filters by `localizedStandardContains` on clean+raw; edit inline
  rewrites the history entry (entries now persist their UUID; old entries matched by ts+raw);
  delete removes card + history entry, no confirm dialog; a «خام» toggle flips clean↔raw —
  the before/after view at recording level.
- **Before/after log:** every LLM call appends `{ts, kind, in_text, context, out_text, in,
  out}` to `~/Library/Application Support/tuti/llm_calls.jsonl` — per-delta granularity for
  prompt testing (jq it).
- **Tokens:** parsed from the API response (Anthropic `usage.input/output_tokens`, OpenAI
  `prompt/completion`), accumulated server-side, pushed as `{"type":"usage","in":N,"out":N}`
  (cumulative) after each call, shown in the menu bar.
- **Paragraphs:** pure Swift formatter — a break after every 3 sentence enders (`. ! ؟`,
  runs of dots collapse; digit-adjacent dots ignored). Applied once when a card finalizes;
  the paragraphed text is what's saved to history. No LLM pass, locked text untouched.
- **TTS read-back: NOT BUILT** — checked `say -v '?'`: macOS ships no Persian voice; the
  feature would mangle Persian. Revisit if he installs a voice or asks for an API TTS.
