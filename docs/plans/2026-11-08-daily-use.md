# Tuti daily-use improvements — Implementation Plan

> Execute task-by-task, in order; checkbox steps. Git rule for this repo: nothing is committed,
> pushed or branched without Amir's explicit ask — everything stays in the working tree.

**Goal:** six small changes that make the stage-1 app nicer to use every day: fast startup without
the network, the transcript on the clipboard, Space for Record/Stop, auto-stop after silence, a
server log with Retry, and a history file.

**Architecture:** Swift only, in the existing files; `server.py` and the protocol do not change.
The sidecar launch gets offline flags and a log file, the view model gets clipboard, history and
auto-stop logic, and the window gets a few small controls.

**Tech Stack:** SwiftUI + Observation (macOS 14), AppKit (`NSPasteboard`, `NSWorkspace`),
Foundation (`Process`, `FileHandle`, `UserDefaults`); xcodebuild. The Python side (`server.py`,
PEP-723, run by `uv`) is untouched.

**Spec:** conversation of 2026-11-08. Amir asked for code suggestions, then: "write the
suggestions into a plan in the repo, another agent will build it". The six suggestions, numbered
as he saw them, are the six tasks. Measurements come from that session (server alone on port
8766, Apple Silicon, MPS).

## Global Constraints

- Personal use, app only: never a browser or web UI, no auth, no multi-user. Hard-coded paths
  live in `Config` (`swift/App.swift`); new paths go there too.
- No global hotkey (Amir: "فعلا هات کی نمی‌سازیم"). Task 3's Space works only while the tuti
  window is focused.
- Closing the window quits the app, the server and the mic (single `Window` scene). Keep it.
- The server refuses any `Origin` header (`origins=[None]` in `server.py`). Keep it.
- Protocol v1 unchanged: `asr_partial` carries the whole transcript so far and replaces the last
  one; one `asr_final` per recording; `error` uses `message`.
- No model work, no changes in the ASR repo (`nemotron-asr-streaming-farsi`): Amir closed that topic.
- No third-party Swift packages, no new Python dependencies, no `server.py` changes.
- No new test files unless Amir asks. Verification = the build plus each task's checks; Amir tests
  the mic and the UI himself.
- Amir's own tuti app may be running and holding port 8765. Never kill it. Test servers run with
  `--port 8766` and are cleaned up with `pkill -f "server.py --port 8766"`. Launch the built app
  only when `pgrep -f tuti.app/Contents/MacOS/tuti` prints nothing.
- Match the surrounding code: one-line comments for the why; a multi-line why becomes a named
  function with a docblock.
- Window layout after this plan. Status row: dot, status text, Spacer, dB (while recording),
  then small controls `Auto-stop` (`.checkbox` toggle, Task 4), `History` and `Clear`
  (`.borderless` buttons, Tasks 6 and 2). Error row: red text, plus `Retry` and `Show Log` when the
  server failed (Task 5). The Record/Stop button stays the big full-width control.

**Build** (every task; no task adds files, so no `xcodegen generate`):

    cd ~/Documents/repos/tuti
    xcodebuild -project tuti.xcodeproj -scheme tuti -configuration Debug -derivedDataPath build build

Expect `** BUILD SUCCEEDED **` and no new warnings (an AppIntents metadata warning is old and
unrelated). A running copy of the app keeps working; Amir relaunches it to get the changes.

## Review Focus

1. Model or Python packages missing from the local caches (new Mac, caches cleared): with Task 1's
   flags the server exits within seconds. The window says why and how to fix it (Task 5 message),
   and Retry works once Amir has run `uv run server.py` by hand.
2. A thinking pause or soft speech: auto-stop must not cut the sentence. Only 2 s under -40 dB
   after speech stops a recording, and both numbers sit in one place for Amir to tune (Task 4).
3. Level updates that arrive after Stop (they are queued Tasks) must not stop or start anything
   again (Task 4).
4. Space while another control has focus, or with transcript text selected, still toggles
   Record/Stop and types nothing (Task 3).
5. The log file can't be created or opened: the server still starts, without a log (Task 5).

| How the server starts | Network | Time |

| `uv run --offline` + `HF_HUB_OFFLINE=1` | none (dead proxy) | 6.1 s |

### Task 4: Auto-stop after silence

> Dropped by Amir before execution (2026-11-08): no auto-stop.

**Files:** Modify `swift/TranscriptViewModel.swift` (`appStart` level callback, `toggleRecord`),
`swift/App.swift` (`Auto-stop` toggle)

**Interfaces:** Produces `var autoStop: Bool` on `TranscriptViewModel` (persisted in
`UserDefaults` under `"autoStop"`, default `true`) and `private func levelChanged(_ db: Float)`.

- [ ] **Step 1:** Constants in `TranscriptViewModel`: `quietDb: Float = -40` (peak dBFS of one mic
      chunk; below it counts as quiet) and `silenceToStop: TimeInterval = 2`. State
      `heardSpeech: Bool` and `quietSince: Date?`, both reset when a recording starts.
- [ ] **Step 2:** `mic.onLevel` hops to the main actor and calls `levelChanged(db)` instead of only
      setting `levelDb`. `levelChanged` sets `levelDb`; then, only when
      `autoStop && phase == .recording`:

      if db >= quietDb: heardSpeech = true; quietSince = nil
      else if heardSpeech:
          quietSince = quietSince ?? now
          if now - quietSince >= silenceToStop: toggleRecord()   // the same path as clicking Stop

  `toggleRecord()` moves the phase to `.finalizing`, so a late level update can't fire it
  again (Review Focus 3). A recording with no speech yet never auto-stops.
- [ ] **Step 3:** `autoStop` is read from `UserDefaults` at init and written on change. In
      `ContentView`: `Toggle("Auto-stop", isOn: Bindable(model).autoStop).toggleStyle(.checkbox)`.
- [ ] **Step 4:** Build.
- [ ] **Step 5:** Amir checks Review Focus 2 with his mic: speak, pause 2 s, and it stops by
      itself; short pauses and soft speech don't stop it; never speaking keeps recording; with
      the checkbox off only Stop stops; the setting survives a relaunch. If his room noise or
      quiet speech sits near -40 dB (the meter shows it while recording), he tunes `quietDb`.
